# Анимация в уроках АРХИМЕД: как делать подробно

Документ собран после изучения скилов проекта (`animate`, `motion-principles`,
`svg-creator`, `ui-typography-usability`) и после разбора собственных ошибок
в уроках 931, 826, 993, 994. Каждое правило проверяемое: его можно подтвердить
замером или снимком.

---

## 1. Зачем в уроке движение

Анимация в уроке — **объяснение**, а не украшение. Она отвечает на вопрос
«что здесь происходит с числом или словом». Разрешённые назначения:

| Назначение | Что показывает | Пример из наших уроков |
|---|---|---|
| **Обмен** | одно превращается в другое | 931 кадр 2: 10 палочек → 1 пучок |
| **Порядок** | что идёт за чем | 931 кадр 7: рамка чтения идёт по классам слева направо |
| **Выбор** | какая цифра решает | 994 кадр 5: пульс решающей цифры, стрелка вверх |
| **Связь** | две стороны одного | 993 кадр 5: точки идут навстречу (6 ⇄ 12) |
| **Результат** | что получилось | 826 кадр 8: рамка вокруг канонической записи |
| **Счёт** | сколько чего | 931 кадр 2: палочки пульсируют по одной |

Если движение нельзя назвать одним из этих слов — его не должно быть.
Проверка обратным ходом: **убери движение; смысл кадра потерялся?**
Потерялся — оставляй. Не потерялся — это украшение, убирай.

Частота в уроке: кадр ребёнок видит один раз, поэтому здесь разрешены
длинные циклы (5–9 с), в отличие от интерфейса приложения, где всё
короче 300 мс.

## 2. Чем анимировать: инструмент по задаче

| Задача | Инструмент | Почему |
|---|---|---|
| Движение предмета внутри рисунка (точка летит, подсветка едет, цифра пульсирует) | **SMIL внутри SVG**: `<animate>`, `<animateTransform>` | живёт вместе с рисунком, не требует JS-состояния, переживает перерисовку кадра |
| Появление блоков кадра, пульс прогресса, отклик кнопки | **CSS**: `@keyframes`, `transition` | дёшево, отключается одним медиазапросом |
| Смена кадра, ответ на нажатие | **CSS transition 100–160 мс** | отклик обязан быть мгновенным |
| JS-анимация (`requestAnimationFrame`, таймеры) | **не используем** | роняет кадры, требует очистки, конфликтует с перерисовкой |

Старые комиксы (`MVP/js/comic.js`) анимируют CSS-классами прямо на группах SVG
и используют **отрицательную задержку** для сдвига фазы:

```js
<g style="animation:c2fish 4.5s ease-in-out -1.5s infinite alternate">
```

Это лучший способ пустить несколько одинаковых предметов «вразнобой» без
SMIL: `-1.5s` сдвигает фазу, а не ждёт начала. Берём приём на вооружение для
CSS-части.

## 3. Время и кривые

| Что | Длительность | Кривая |
|---|---|---|
| Появление блока кадра | 280 мс | `cubic-bezier(.23,1,.32,1)` |
| Отклик кнопки | 100–160 мс | та же; сдвиг на 2 px |
| Пульс (подсветка, внимание) | 1.4–2.4 с | `ease-in-out`, бесконечно |
| Полёт точки, ход подсветки | 5–7 с | с паузами через `keyTimes` |
| Поочерёдность (счёт, шаги) | шаг 0.3–0.9 с | линейно по `begin` |
| Полный цикл составной сцены | 6–9 с | пауза в конце цикла обязательна |

Паузы задаются `keyTimes` — без них движение читается как мельтешение:

```js
анТ('0 0;0 0;288 0;288 0;0 0','7s',
    'keyTimes="0;0.08;0.6;0.86;1"')   // поехал, постоял, вернулся
```

Запрещено: `ease-in` на появлении (элемент «тормозит» ровно там, куда смотрит
ребёнок); `transition: all`; анимация `width/height/top/left/margin`; `scale(0)`.

Кривые проекта (не встроенные `ease`):

```css
--ease-out:    cubic-bezier(.23, 1, .32, 1);
--ease-in-out: cubic-bezier(.77, 0, .175, 1);
```

## 4. Пять обязательных правил урока

1. **Всегда видимо.** Ни одно состояние кадра не должно быть невидимым:
   минимум прозрачности 0.3, никаких «появляется из ничего». Причина бытовая:
   ребёнок и проверяющий видят кадр в любой момент, а при отключённом движении
   он обязан быть целым и понятным.
2. **Текст не масштабируем.** Ни `transform: scale()`, ни `font-size` в
   анимации — текст мылится. Текст можно пульсировать прозрачностью и
   подсвечивать рамкой.
3. **Движение только вертикальное или вдоль оси.** Горизонтальный сдвиг на всю
   ширину выносит элемент за край рамки (ловилось в 877 и 879).
4. **Ничего за край кадра.** Проверяется замером: ни один элемент не выходит
   за `#lvis .s6` больше чем на 1 px в любой момент анимации.
5. **`prefers-reduced-motion` — движение выключается полностью.** У нас это
   флаг `ДВИЖ`: при включённой настройке SMIL-теги **не выводятся вовсе**,
   кадр сразу показывает конечное состояние. CSS-часть гасится медиазапросом.

## 5. Каталог примитивов

Стандартный блок помощников, который копируется в урок (проверено в 826, 931,
993, 994):

```js
const ДВИЖ = !(window.matchMedia && window.matchMedia('(prefers-reduced-motion: reduce)').matches);
const ан   = (имя,значения,длит,доп) => ДВИЖ ? `<animate attributeName="${имя}" values="${значения}" dur="${длит}" repeatCount="indefinite" ${доп||''}/>` : '';
const анТ  = (значения,длит,доп)    => ДВИЖ ? `<animateTransform attributeName="transform" type="translate" values="${значения}" dur="${длит}" repeatCount="indefinite" ${доп||''}/>` : '';
const пульс   = (длит,нач) => ан('opacity','1;0.35;1',длит, нач!=null?'begin="'+нач+'s"':'');
const кольцо  = (x,y,r,цвет,длит,нач) => /* вспышка: opacity 0→0.9→0 и r → r+9 → r */;
const летит   = (x0,y0,x1,y1,длит,нач) => /* точка едет из точки в точку и возвращается */;
```

Держим в файле **только те помощники, которые вызываются**: объявленный и не
использованный помощник — это мёртвый код, который потом путает (так уже было
с `появление` в 931 и `едетПолоса` в 826 и 993 — убраны).

Ходячая подсветка («подсветка едет по строкам») пишется прямо на месте:
рамка нужного размера с `анТ` внутри группы.

```js
<g>${анТ('0 0;0 0;0 27;0 27;0 54;0 54;0 81;0 81;0 108;0 108;0 0','9s',
       'keyTimes="0;0.05;0.15;0.25;0.35;0.45;0.55;0.65;0.75;0.9;1"')}
  <rect x="18" y="36" width="300" height="27" rx="8" fill="none" stroke="${GOLD}" stroke-width="2.2"/>
</g>
```

| Примитив | Что объясняет | Где применён |
|---|---|---|
| `пульс` | «смотри сюда», счёт по одному | 826 кадры 1, 2, 6; 993 кадры 1, 2, 8 |
| `кольцо` | «вот результат» | 931 кадры 2, 4, 6; 826 кадры 1, 6, 7 |
| `летит` | переход, связь, сборка | 931 кадры 2, 3, 9; 993 кадры 5, 6; 994 кадр 10 |
| ходячая рамка (`анТ` + `rect`) | порядок: подсветка идёт по строкам | 826 кадр 4; 994 кадры 6, 8 |
| поочерёдный `begin` | счёт, шаги, «сначала… потом…» | 931 кадр 2; 826 кадр 5; 993 кадр 2 |
| CSS-пульс точки уровня | прогресс в практике и тренажёре | 826, 931, 993, 994, кадры практики |

Замер на версии v699: 826 — 58 SMIL-анимаций на 12 кадрах, 931 — 64 на 12,
993 — 53 на 10, 994 — 20 на 12; кадров без анимации нет ни в одном уроке,
при `prefers-reduced-motion` анимаций 0.

### Пример полной сцены (931, кадр 2): что происходит по секундам

```
0.0–3.0 с   палочки пульсируют по очереди (begin = 0.0, 0.3, … 2.7) — счёт
0.0–3.6 с   золотая точка идёт от палочек к пучку (keyTimes 0.08 → 0.55)
2.4–3.6 с   кольцо вспыхивает на пучке (keyTimes 0.5 → 0.68)
3.6 с       цикл повторяется
```

Правило сцены: **одно главное движение + одна вспышка результата**; больше
двух одновременных движений в кадре ребёнок не различает.

## 6. Проверка анимации перед выкладкой

Прогон обязателен для каждого нового урока. Порядок такой:

**Шаг 1. Числовой замер** (обе настройки движения):

```
анимаций на кадр: > 0 в каждом кадре (в practice/тренажёре допускается CSS-пульс)
при prefers-reduced-motion: 0 SMIL-тегов
элементов за краем кадра: 0
наложений подписей: 0
частичных наложений фигур: не больше 8 % площади меньшей (тени-двойники и
   вложенная подсветка исключаются)
кегли в SVG: только 12/14/16/20/24/32
переполнение страницы: 0 на 390, 768, 1200 px
ошибок JS: 0
```

**Шаг 2. Контактный лист.** Все рисунки урока собираются в одну сетку
(3 колонки) и снимаются **в двух моментах** — примерно 0.6 с и 2.6 с после
старта. Это ловит то, чего не видит ни один замер: бессмысленный уход в
сторону, наложение колец, обрезку краем, «гармошку» из фигур.

**Шаг 3. Крупный снимок** подозрительных кадров (`.pic` целиком) — по одному
на кадр, если в листе что-то смутило.

**Шаг 4. Живой проход** урока на 390 px: все шаги, все ответы, практика,
тренажёр, счёт.

## 7. Восемь ошибок, которые уже случались

| # | Ошибка | Как выглядит | Чем ловится |
|---|---|---|---|
| 1 | Движение никуда не ведёт (`translateX` на 56 px и обратно) | предмет «дёргается» без смысла | взгляд на лист рисунков |
| 2 | Цель полёта задана **дельтой вместо координаты** | точки разлетаются вразнобой | замер геометрии + лист |
| 3 | Дублирующиеся кольца с общим периодом | несколько кругов одновременно | лист |
| 4 | Кольцо больше объекта | круг перекрывает цифры | крупный снимок кадра |
| 5 | Посимвольная отрисовка с шагом меньше ширины буквы | цифры налезают (шаг 13 px при кегле 20) | замер наложений подписей |
| 6 | Координата в **абсолютных** единицах внутри сдвинутой группы | элемент уезжает вдвое ниже | замер наложений |
| 7 | Слишком сильное приглушение (opacity 0.35) | кадр выглядит пустым | лист рисунков |
| 8 | Помощник не определён в файле | кадр падает, рендер пустой | счётчик битых кадров в замере |

Общий вывод: **числовые замеры не заменяют глаз**. Три из восьми ошибок
числовой замер пропустил полностью.
