# Подход к турам АРХИМЕД

Как делать тур так, чтобы он получался сразу и не приходилось переделывать.
Записано по опыту четырёх туров: 701 (3 класс), 702 (4 класс), 703 (5 класс),
704 (6 класс).

## 1. Тур — это не урок

| | Урок | Тур |
|---|---|---|
| Смысл | одна тема | пять заданий на баллы |
| Подача | объяснение и задачи | сюжет, свои сцены, разбор |
| Устройство | кадры одной истории | 12 шагов: знакомство, 5× (теория + задача), итог |
| Баллы | нет | по 2 балла за задание, всего 10 |

Тур живёт **отдельным файлом** `MVP/data/tour_mathN_имя.js` и не смешивается с
уроками. Один тур = один модуль.

## 2. Каркас модуля

```
(function(){
  'use strict';
  const ID = 70N, ДОМ = 't70N';          // ДОМ — префикс всех классов и id градиентов

  /* пять заданий: условие, вопрос, ответ, разбор, ошибка */
  const ЗАДАЧИ = [ ... ];

  /* помощники: esc, ОПРЕДЕЛЕНИЯ (градиенты и фильтры), svg, т, рамка, круг,
     линияРисуется, ДЕТИ + дитя, разбор, жетон, операция */

  /* предметы сюжета: свои для каждого тура, с градиентами и тенями */

  const ШАГИ = [];                        // 12 шагов
  ШАГИ.push({ т:'Название', рисунок(){...}, низ(){...} });

  /* проверки ответов, память() и перерисовать(), баллТура(), счётДо() */
  window.Т70N = { ... };                  // действия руками

  /* запись в ARH_TOURS — иначе тур не виден в разделе «Тур» */
  /* window.WAVE_B[ID] — рендерер шага */
  /* перехват ARH_LESSONS — регистрация в каталоге */
})();
```

Помощники берутся из готового модуля копированием (они обкатаны) и правятся
под сюжет. **Не копировать `разбор` и `жетон` дважды** — проверять
`node --check`, иначе объявление конфликтует.

## 3. Обязательные шаги (12)

1. **Знакомство** — сцена сюжета, две фразы: что за место и что задач пять.
2, 4, 6, 8, 10. **Теория** — приём, который нужен именно этой задаче.
3, 5, 7, 9, 11. **Задача** — ввод ответа руками, проверка, разбор.
12. **Итог** — медаль, балл насчитывается от 0, пять отметок ✓/✕.

## 4. Правила сцены

- Кадр — svg шириной 336, высота своя (170–210). Полосы разводить заранее и
  записывать их в комментарии: `заголовок 24 · рисунок 60 · земля 118 · подпись 186`.
- **Ничего не налезает.** Подписи короче, если упираются в край: ширина строки
  при кегле 12 — примерно 6,2 px на знак, значит в 320 px влезает ~50 знаков.
- **Кадр внутри viewBox.** Частая ошибка: рамка 8…204, а `svg(s, 196)`.
- Предметы рисовать, а не обозначать: дом с крышей и окном, лампочка с колбой,
  гриб со шляпкой. Кружки-заглушки запрещены.
- Свет и объём: градиенты, мягкие тени через `feGaussianBlur`, зерно через
  `feTurbulence`, конусы света.
- Кегли только 12 / 14 / 16 / 20 / 24 / 32.
- **Живой язык.** Запрещены: «Как это работает», «Приём: …», «Условие»,
  «максимум N баллов», «источник», «ответ проверяется сразу».
- Не меньше **двух осмысленных анимаций** на шаг: свет, качание, прорисовка
  линии, отклик на ответ. Уважать `prefers-reduced-motion`: без анимации в
  кадре не должно быть каши (строки разбора, которые показываются по очереди,
  при выключенных анимациях оставляют одну).

## 5. Ответы руками

- Каждый шаг-задача держит ввод в `низ()` (DOM), а не в svg.
- Состояние живёт в `CHS[lidKey(ID)]`: `ответы`, `проверено`.
- Действие меняет состояние и вызывает `перерисовать()` = `chRender(0)`.
- Проверять ответ **нормализованно**: «32,18» и «32.18» — одно и то же,
  «15 февраля» / «15.02» — тоже.
- Цель нажатия не меньше 44 px (кнопка, поле — 48).
- Переключатели перебирают состояния по кругу: 1 → 2 → 3 → 1, и первое
  нажатие должно уводить от состояния по умолчанию, а не «оставлять на месте».

## 6. Регистрация — три места, забыть любое значит «тур пропал»

1. `window.WAVE_B[ID]` — рендерер шага.
2. `ARH_LESSONS` — каталог (перехват сеттера, подстановка своего объекта с
   `explain: ЛЕНТА`).
3. `window.ARH_TOURS.push({...})` — список раздела «Тур». Без этого тур есть
   в каталоге, но в разделе «Тур» его не видно.
4. Сборка: добавить файл тур-данных в `РУЧНЫЕ` в `план-1-9/build_tours.js`,
   иначе сборщик сделает поверх свою карточку.
5. `index.html`: подключить модуль **после** `tours_olymp.js` (он задаёт
   `ARH_TOURS`).
6. Версию поднять в `MVP/index.html` и `MVP/sw.js`.

## 7. Проверка перед выкладкой

Замер по каждому шагу (инструмент — `браузеры/шаг701.py`, меняется ID):

| Что | Норма |
|---|---|
| Наложения подписей | 0 |
| Элементы за краем кадра | 0 |
| Кегли вне шкалы | 0 |
| Цели меньше 44 px | 0 |
| Анимаций на шаг | ≥ 2 |
| Ошибки JS | 0 |
| Сквозной проход верными ответами | разбор на всех 5 заданиях, итог 10 из 10 |

Плюс глазами: снимок 390×844 и крупный план сцены. Смотреть именно сцену —
ошибки вида «фрукты на головах» замером не ловятся.

## 8. Грабли, на которые уже наступали

1. Помощник не определён (`разбор`, `жетон`) — шаг с ответом падает в пустой
   кадр. Смотреть консоль: `тур 70N: ReferenceError`.
2. `toFixed` у строки — шаг не рисуется вовсе.
3. Дубли объявлений после копирования каркаса — `node --check` покажет.
4. Первое нажатие не меняет состояние — задание нерешаемо.
5. Кадр шире/выше viewBox — низ обрезан.
6. Подписи шире кадра.
7. Локализованное выравнивание: у `т()` один параметр якоря, лишний `false`
   ломает подпись.
8. Точки прогресса вместо слов — ребёнку непонятно.
9. Строки разбора, видимые все сразу до старта анимации.
10. Забыли `ARH_TOURS` — тур «пропал» из раздела.
11. Не вызван `счётДо` — в итоге стоит 0 при верных ответах.
12. Предметы налезают на фигуры (фрукты на головах) — видно только глазами.

## 9. Порядок работы

1. Прочитать задания тура из `deploy/ТУР_*.json`.
2. Придумать сюжет и пять сцен; расписать полосы каждой сцены.
3. Собрать модуль: данные → помощники → предметы → 12 шагов → действия →
   регистрация.
4. Прогнать замер по всем шагам, починить дефекты, снова замерить.
5. Пройти тур верными ответами: разбор на всех заданиях, итог 10 из 10.
6. Снимки и просмотр глазами.
7. Поднять версию, коммит по-русски, выкладка, проверка на проде.
